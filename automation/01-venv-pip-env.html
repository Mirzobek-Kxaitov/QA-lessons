Python asoslari

Python'da VENV, PIP va .ENV

Har bir loyiha uchun alohida muhit yarating, kerakli package'larni o'rnating va parol kabi maxfiy ma'lumotlarni xavfsiz saqlang.

1-dars ~30 daqiqa nazariya + 15 daqiqa amaliyot Talab: kompyuterda Python o'rnatilgan bo'lishi

Kirish: nima uchun bu 3 ta narsa kerak?

Tasavvur qiling, siz ikkita QA automation loyihasida ishlayapsiz:

Project A  →  Selenium 4.10 kerak
Project B  →  Selenium 4.20 kerak

Agar ikkalasi ham bitta umumiy Python muhitidan foydalansa, bitta versiya ikkinchisining ustiga yoziladi. Natijada bugun ishlagan testlar ertaga sababsiz "sinadi".

Xuddi shu loyihalarda login uchun parol kerak. Agar parolni to'g'ridan-to'g'ri kod ichiga yozsangiz, kodni GitHub'ga yuklaganingizda parol hammaga ochiq bo'lib qoladi.

Bu ikki muammoni hal qiladigan uchta vosita bor:

VositaVazifasi
VENVHar bir loyihaga alohida muhit beradi
PIPShu muhitga package o'rnatadi
.ENVMaxfiy ma'lumotlarni koddan ajratib saqlaydi

1. VENV — loyihaning shaxsiy qutisi

VENV nima?

VENV (virtual environment) — bitta loyiha uchun ajratilgan alohida Python muhiti.

Buni uydagi qutilarga o'xshating:

📦 1-quti → Kiyimlar
📦 2-quti → Idish-tovoqlar
📦 3-quti → O'yinchoqlar

Har bir qutida faqat o'ziga tegishli buyum turadi va ular aralashib ketmaydi. Python loyihalarida ham xuddi shunday:

📦 Project A
   └── venv
       └── Selenium 4.10

📦 Project B
   └── venv
       └── Selenium 4.20

Endi ikkala loyiha bir-biriga xalaqit bermaydi.

VENV yaratish

Loyiha papkasini oching va terminalda yozing:

python -m venv venv

Bu buyruq loyihangiz ichida venv/ nomli papka yaratadi. Ichida alohida Python va bo'sh package ro'yxati bo'ladi.

Eslatma

Ba'zi kompyuterlarda python o'rniga python3 yozish kerak bo'ladi.

VENV'ni aktivlashtirish ⚠️

Bu darsdagi eng muhim qadam. VENV yaratilgani bilan avtomatik ishlamaydi — uni har safar qo'lda yoqish kerak.

Windows (CMD / PowerShell):

venv\Scripts\activate

Mac / Linux:

source venv/bin/activate

Aktiv bo'lganini qanday bilamiz?

Terminal satrining boshida (venv) paydo bo'ladi:

(venv) C:\qa_project>

Mana shu (venv) yozuvi — "quti ochiq, ishlashga tayyor" degani. Agar u ko'rinmasa, VENV o'chiq va o'rnatgan package'laringiz noto'g'ri joyga tushadi.

Qo'shimcha tekshirish:

pip list

Yangi VENV'da ro'yxat deyarli bo'sh bo'ladi — bu normal holat.

VENV'dan chiqish

deactivate

(venv) yozuvi yo'qoladi. Ishni davom ettirmoqchi bo'lsangiz, yuqoridagi aktivlashtirish buyrug'ini qayta yozasiz.

2. PIP — qutini to'ldiruvchi vosita

PIP nima?

Bizda quti bor. Endi uni to'ldirish kerak. Bu ishni PIP bajaradi.

PIP — Python package'larini internetdan yuklab olib, muhitga o'rnatadigan vosita. U Python bilan birga keladi, alohida o'rnatish shart emas.

📦 VENV  → quti
🔧 PIP   → qutiga buyum keltiruvchi
🧸 Selenium, Pytest → qutidagi buyumlar

Asosiy buyruqlar

Package o'rnatish:

pip install selenium

Bir vaqtda bir nechtasini o'rnatish:

pip install selenium pytest python-dotenv

Aniq versiyani o'rnatish:

pip install selenium==4.10.0

O'rnatilganlarni ko'rish:

pip list

Package'ni o'chirish:

pip uninstall selenium
Muhim

pip install yozishdan oldin (venv) ko'rinib turganiga ishonch hosil qiling. Aks holda package butun kompyuterga o'rnatiladi va VENV'ning mantig'i buziladi.

requirements.txt — buyumlar ro'yxati

Loyihada 10-15 ta package bo'lishi mumkin. Yangi hamkasbingiz loyihani ochganda ularning har birini qo'lda yozib chiqishi kerakmi? Yo'q.

Ro'yxatni saqlash:

pip freeze > requirements.txt

Fayl ichida shunga o'xshash yozuv paydo bo'ladi:

selenium==4.20.0
pytest==8.2.0
python-dotenv==1.0.1

Ro'yxat bo'yicha hammasini o'rnatish:

pip install -r requirements.txt

Bir buyruq — va yangi kompyuterda loyihaning butun muhiti tayyor.

Amaliy qoida

Yangi package o'rnatgan har safaringizda pip freeze > requirements.txt ni qayta ishlating, aks holda ro'yxat eskirib qoladi.

3. .ENV — loyihaning seyfi

Muammo

QA automation loyihasida saytga login qilish kerak. Ko'pchilik shunday yozadi:

username = "admin"
password = "123456"
url = "https://example.com"

Bu xavfli va noqulay:

  • Kodni GitHub'ga yuklasangiz, parol hammaga ochiq bo'ladi
  • Test muhitidan production'ga o'tishda kodning o'zini o'zgartirishga to'g'ri keladi
  • Jamoadagi har bir kishining o'z logini bo'lsa, fayl doim konflikt beradi

Yechim: .env fayli

.ENV — sozlamalar va maxfiy ma'lumotlar saqlanadigan oddiy matn fayli. U koddan tashqarida turadi.

Loyiha papkasida .env nomli fayl yarating (nomi aynan shunday, nuqta bilan boshlanadi):

URL=https://example.com
USERNAME=admin
PASSWORD=123456

Yozish qoidalari:

  • KALIT=qiymat shaklida, tenglik belgisi atrofida bo'sh joy qo'yilmaydi
  • Qiymat qo'shtirnoqqa olinmaydi
  • Har bir sozlama alohida qatorda
✅ To'g'ri:   USERNAME=admin
❌ Noto'g'ri: USERNAME = "admin"

.env faylini Python'da o'qish

Buning uchun alohida package kerak:

pip install python-dotenv

Endi kodda:

from dotenv import load_dotenv
import os

load_dotenv()          # .env faylini yuklaydi

URL = os.getenv("URL")
USERNAME = os.getenv("USERNAME")
PASSWORD = os.getenv("PASSWORD")

print(URL)             # https://example.com

Endi parol kodda emas, .env faylida. Kodda faqat uning nomi qoladi.

.gitignore — eng muhim qadam ⚠️

.env ning butun mantig'i shunda: u hech qachon Git'ga tushmasligi kerak. Buni ta'minlash uchun loyiha papkasida .gitignore fayli yaratiladi:

venv/
.env
__pycache__/

Endi Git bu fayllarni butunlay e'tiborsiz qoldiradi.

venv/ ni ham qo'shamiz, chunki u minglab fayldan iborat va har bir dasturchi uni requirements.txt orqali o'zi yaratib oladi.

.env.example — jamoa uchun namuna

Agar .env Git'ga tushmasa, yangi hamkasb qanday sozlamalar kerakligini qayerdan biladi? Buning uchun .env.example fayli yaratiladi — ichida faqat kalitlar, qiymatsiz:

URL=
USERNAME=
PASSWORD=

Bu fayl Git'ga yuklanadi. Yangi hamkasb uni nusxalab, .env deb nomlaydi va o'z qiymatlarini yozadi.

4. Boshlovchilar qiladigan 5 ta xato

XatoNima bo'ladiYechim
VENV'ni aktivlashtirmasdan pip install qilish Package global muhitga tushadi Avval (venv) borligini tekshiring
.env ni Git'ga yuklab yuborish Parol hammaga ochiq bo'ladi .gitignore ga .env qo'shing
.env da qo'shtirnoq ishlatish Qiymat qo'shtirnoq bilan o'qiladi USERNAME=admin deb yozing
venv/ papkasini Git'ga yuklash Repository og'irlashadi .gitignore ga venv/ qo'shing
requirements.txt ni yangilamaslik Hamkasbda loyiha ishlamaydi Har o'rnatishdan keyin pip freeze

5. Amaliyot: 7 qadamda to'liq loyiha

Quyidagi qadamlarni terminalda ketma-ket bajaring.

1. Loyiha papkasini yarating

mkdir qa_project
cd qa_project

2. VENV yarating

python -m venv venv

3. VENV'ni aktivlashtiring

venv\Scripts\activate          # Windows
source venv/bin/activate       # Mac / Linux

Terminalda (venv) paydo bo'lganini tekshiring.

4. Package'larni o'rnating

pip install selenium pytest python-dotenv

5. Ro'yxatni saqlang

pip freeze > requirements.txt

6. .env va .gitignore fayllarini yarating

.env:

URL=https://example.com
USERNAME=admin
PASSWORD=123456

.gitignore:

venv/
.env
__pycache__/

7. Tekshiring

test_env.py faylini yarating:

from dotenv import load_dotenv
import os

load_dotenv()

print("URL:", os.getenv("URL"))
print("USERNAME:", os.getenv("USERNAME"))

Ishga tushiring:

python test_env.py

Ekranda quyidagi natija chiqishi kerak:

URL: https://example.com
USERNAME: admin

✅ Chiqdi — demak hamma narsa to'g'ri sozlangan.

6. Loyiha strukturasi

Amaliyotdan keyin loyihangiz shunday ko'rinishda bo'ladi:

qa_project/
│
├── venv/               ← alohida Python muhiti (Git'ga tushmaydi)
├── tests/              ← test fayllar
├── pages/              ← Page Object klasslari
├── .env                ← maxfiy ma'lumotlar (Git'ga tushmaydi)
├── .env.example        ← namuna (Git'ga tushadi)
├── .gitignore          ← nimani e'tiborsiz qoldirishni belgilaydi
└── requirements.txt    ← package'lar ro'yxati

Xulosa

📦 VENV             → loyihaning alohida muhiti (quti)
🔧 PIP              → qutiga package o'rnatadi
📋 requirements.txt → qutidagi buyumlar ro'yxati
🔑 .env             → parol va sozlamalar seyfi
🚫 .gitignore       → nimani Git'dan yashirishni belgilaydi
Dars oxirida siz quyidagi savollarga javob bera olishingiz kerak
  1. VENV nima va nima uchun kerak?
  2. VENV'ni qanday aktivlashtiramiz va aktiv ekanini qanday bilamiz?
  3. pip freeze va pip install -r nima qiladi?
  4. Nima uchun parolni kod ichiga yozmaymiz?
  5. Nima uchun .env faylini .gitignore ga qo'shish shart?

Uy vazifasi

  1. Yangi my_first_project papkasini yarating va yuqoridagi 7 qadamni mustaqil takrorlang.
  2. .env ga BROWSER=chrome qatorini qo'shing va uni Python orqali ekranga chiqaring.
  3. pip uninstall pytest qilib ko'ring, keyin pip install -r requirements.txt orqali qayta tiklang.

Keyingi dars: Selenium WebDriver bilan birinchi avtotest yozish.
